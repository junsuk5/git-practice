## 1. 오늘 내가 직접 손으로 치며 배운 점

- `winget install Git.Git`
  - 명령어로 Git을 설치하는 방법을 알게 되었다. 공식 웹사이트를 이용하는 방법만 생각했었는데, 터미널 명령어를 활용할 생각은 왜 하지 못했을까 하는 생각이 들었다.

- `git config --global init.defaultBranch master`
  - 명령어로 기본 브랜치 이름을 명시적으로 설정하는 방법을 알게 되었다. 사용자 이름과 이메일 등록만 생각했었는데, 다른 설정 항목들을 찾아보지 않았던 점이 아쉬웠다.

- `git config --global core.autocrlf true`
  - 명령어로 줄바꿈 호환성을 설정하는 방법을 알게 되었다. 기본 브랜치 이름 변경과 비슷한 맥락인데, 확인해 보니 이미 적용되어 있었다. 언제 설정했는지 기억이 희미한데, 앞으로는 어떤 작업을 했는지 잘 기록하고 기억해야겠다고 생각했다.

- `echo`
  - 명령어를 사용하면서 `>` 와 `>>` 의 차이를 알게 되었다. 두 명령어를 종종 보면서도 어떤 차이가 있는지 스스로 찾지 못했던 점이 아쉬웠다.

> Git 명령어를 직접 입력하며 개념을 다시금 되새길 수 있었다. `git checkout`의 여러 기능으로 인해 `git restore` 와 `git switch` 로 분리된 것도 재인지했다. 실은 `소스트리(SourceTree)` 를 주로 사용했는데 `--staged` 는 꽤나 낯설었고, 직접 타이핑하며 의미를 다질 수 있었다.

## 2. 가장 멘붕이었던 순간 & 트러블슈팅

- **문제 상황**:
  - `git restore` 명령어 입력 시 `error: pathspec <파일명> did not match any file(s) known to git` 에러 발생.

- **원인 및 해결**:
  - 추적되지 않은(Untracked) 신규 파일임을 확인, 해당 명령어의 기능을 재인지.

## 3. 나만의 언어로 재해석한 핵심 용어 사전

- **Git**: 내 작업물을 마음대로 넘나들고 제어할 수 있는 도구.
- **Commit**: 하나 하나 기록한 소중한 내 작업물.
- **Staging Area**: 세상에 보여줄 준비가 된 내 작업물, 아직 준비가 되지 않으면 반송.
- **Remote**: 내 작업물을 안전하게 보관하고 어디서든 꺼내볼 수 있는 저장고.
- **Pull Request (PR)**: 내 작업물과 함께 하겠냐고 정중하지만 당당히 보내는 메시지.
