## 1. 오늘 내가 직접 손으로 치며 배운 점
### 1) git branch -> git switch
- branch 생성 : ```git checkout -b <branch>``` == ```git switch -c <branch>```
- branch 이동 : ```git checkout <branch>``` == ```git switch <branch>```
- git switch는 현업에서는 거의 사용하지 않는다, checkout 사용 권장  
    (그치만 switch가 좀 더 직관적인 느낌이라 내 스타일)
### 2) git merge
- 머지를 할 주체 브랜치에서 머지를 당할 브랜치를 당겨오기  
    ```git merge main homework```
    - 위 명령어는 아직 push 안하고 로컬에 머지한 상태
- 머지했을 때 출력 결과 중 'Fast-forward'의 의미  
    : 머지한 주체 브랜치에 다른 커밋이 없었기 때문에 주체 브랜치의 포인터를 최신 커밋 위치로 빠르게 앞당겼다는 의미
### 3) git push -u origin ```<branch>```
: 깃 원격 저장소(origin)에 내 작업 브랜치 ```<branch>```를 푸시
- 옵션 ```-u``` == ```--set-upstream```
- 로컬 ```<branch>```와 원격의 ```origin/<branch>```를 영구적으로 연결
    - ```<branch>```를 원격에 최초 푸시할 때만 하면 됨
### 4) fork 진행 순서
1. fork
2. 내 계정으로 fork된 저장소 url 복사
3. clone
4. new branch 생성
5. 작업(~push 까지)
6. pull request
### 5) git reset
- ```git reset --hard <돌아가고 싶은 커밋 해시>```  
    : 지금까지 작업한 내용 날리고, 입력한 <돌아가고 싶은 커밋 해시> 포인트로 작업 되돌리기
- ```git reset --hard origin/<branch>```  
    : 원격의 ```origin/<branch>```로 복구시키기 (HEAD를 여기로 이동)
    - 이때 ```origin/<branch>```에 복구할 내용이 있어야 복구 가능  
- Q. 그럼 되돌아가서 수정한 내용을 ```origin/<branch>```에 push한 뒤 되돌아가기 전의 내용은 복구 안되나??
    - 복구 가능은 함. 하지만 인간이 하기는 어려움.
    - 로컬의 참조 이력(reflog)가 남아 있다면 해당 작업 내용만 가져오기 가능
    - 커밋 해시를 알고 있으면 돌리기 쉬움. 아니면 .git 파일에서 AI 도움으로 찾으면 됨.
    - 커밋 해시가 들어있는 파일을 reset하기 전에 물리적으로 따로 저장해두는 것도 한 방법.
- reset 조심해서 사용할 것!!!!!
