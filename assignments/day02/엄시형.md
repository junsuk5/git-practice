## 1. 오늘 내가 직접 손으로 치며 배운 점
- `git checkout -b <브랜치명>` : 브랜치 생성 + 이동 (`-b` : 없으면 생성)
- `git checkout <브랜치명>` : 기존 브랜치 이동
- `git merge <브랜치명>` : 기본값은 Fast-Forward로 포인터를 앞으로 당김
- `git checkout -d <브랜치명>` : 브랜치 삭제
- `fork` : 오픈소스 남의 코드를 가져다 쓸 수 있음 내꺼임
- `오픈소스기여 방법`: **fork**를 통해 가져온 다음 브랜치를 따로 만든 후 **PR**을 통해 병합 요청
- 위쪽이이 원본(오픈소스) 아래쪽이 내꺼 
- `mv <대상이름> <새로운이름>` : 이름 변경
- `PR` : 리뷰를 통해 코멘트 가능
- `git reset --hard <해시>` : 강제로 해당 커밋으로 되돌리기
- `git reset --hard <origin/브랜치>` 원격의 최신 브랜치 상태로 복구

## 2. 가장 멘붕이었던 순간 & 트러블슈팅

- **문제 상황** : fork를 하고 작업을 했는데 PR을 못함
- **원인 및 해결** : 디렉터리를 확인을 제대로 안 하고 작업을 해서 기존에 git-practice에서 작업을 진행
  git-practice (.git)
   |
  └── git-practice-home (.git)
  `git-practice-home` 삭제 후 `git-practice`에서 작업을 진행
  push 함 `git-practice`에 올라갔음
  git이 고장 난 줄 알고 `git-practice-homework` 리모트로 변경
  `git-practice`은 내가 작성한 거니깐 PR 요청이 불가
