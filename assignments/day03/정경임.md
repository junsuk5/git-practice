## 3) git 서브모듈

- Git 안에 다른 git 저장소를 디렉토리로 분리해서 넣음 : 현 레포지토리에서 다른 레포지토리로 이동 가능
    - 코드를 프로젝트에 복사하는 대신, git의 하위 모듈이 원래 저장소로 연결되어 필요할 때 업데이트 가져오기 가능
- 여러 프로젝트의 외부 코드를 재사용하거나 의존하고 싶을 때 유용
- 예)
    - 여러 프로젝트가 공유 라이브러리에 의존하는 경우, 서브모듈은 라이브러리 저장소와 연결해 일관성을 보장
    - 외부 도구나 프레임워크를 프로젝트에 통합해야 하는 경우 쉽게 관리하고 업데이트할 수 있게 해줌
    - 서브모듈은 메인 프로젝트와 독립적으로 업데이트 가능 : 서로 다른 의존성 버전 사용 가능
    - 서브모듈은 동일한 외부 코드를 여러 프로젝트에 걸쳐 재사용할 수 있게 해 중복을 줄이고 유지보수 가능성을 높임


- 일반 폴더와 달리 폴더에 화살표가 추가되어 있음.
- 파란색으로 표시됨.
- 서브모듈의 commit hash와 함께 표시됨.
- 클릭 시 해당 repository로 이동

## 4) 소수점 dtype `float` vs `double`

|  | float | double |
| --- | --- | --- |
| byte | 4 | 8 |
| 유효 숫자(소수점 아래 정밀도) | 7자리 정도까지 정확 | 15자리 정도까지 정확 |
| 오차 발생 가능성 | 높음. 계산 반복 시 오차 누적 | 낮음. 대부분의 일반적인 연산에서 안전 |
| 주요 사용처 | 3D 그래픽(수많은 좌표 계산), 모바일 게임 엔진, 센서 데이터 등 메모리와 성능 최적화가 극도로 중요한 곳 | 일반적인 앱/웹 프로그래밍, 금융 연산, 정밀한 수학/과학 데이터 처리 |
- 자바의 실수 타입의 기본 처리는 double 타입
- float과 double 선택할 때
    - 계산의 정확도가 얼마나 필요한지, 입력 값과 중간 값의 범위가 얼마나 넓은지에 따라 달라짐
    - 필요한 정밀도, 크기, 속도에 따라 달라짐
    - 확실하지 않다면 double이 항상 더 정확하고 안전
- float이 더 빠를 수 있음, double은 더 정밀하고 범위가 크다
    - 나누기를 할 때 float은 소수점 7자리까지 나타내고, double은 소수점 16자리까지 표현함
- double이 좀 더 정확하다. 소수점 이슈 때문.
    - 계산을 하면서 정밀도를 유지하는 것이 중요함. 계산을 많이 할 수록 정밀도를 잃게 되기 때문.
    - 부동 소수점은 고정 소수점 방식보다 훨씬 더 많은 범위까지 표현할 수 있지만, “항상 오차가 존재한다”는 단점
    - 업계마다 float이나 double 선호하는 것이 다름
- 요즘은 메모리 용량이 충분하기 때문에 소수점 계산 시 발생할 수 있는 미세한 오차(버그)를 방지하기 위해 기본 실수형으로 double을 사용하는 것이 일반적.

## 5) 문자열 비교는 `StringVar.equals()` 사용 (not `==`)

- == 연산자는 두 문자열의 주소 값이 같은지 비교. 메모리의 동일한 위치인지 비교
- equals는 두 문자열의 내용을 비교
- 그렇다면 숫자는 왜 == 사용이 가능한가?
    - 기본형 숫자(int, double 등)의 저장 위치는 Stack 메모리
        - 변수 공간 자체에 실제 숫자 값(2진수)를 저장
    - 문자열은 Heap 메모리에 저장.
        - 변수 자체는 실제 문자열이 아니라 힙 영역에 생성된 객체의 메모리 주소값을 가짐

## 6) 메서드와 함수

: 보통 혼용해서 쓰지만 둘은 사실 다르다

1. 함수 function
    - 입력을 받아 작업을 수행하고 결과를 반환하는 “독립적”인 코드 블록
    - 전역적으로 정의되거나 다른 함수 내부에서 정의될 수 있다
    - 어떤 클래스에 속하지 않을 수 있다
2. 메서드 method
    - 특정 객체에 속한 함수
    - 클래스의 일부
    - 해당 클래스의 객체(인스턴스)를 통해서만 호출 가능 : 메서드가 객체의 상태(속성, 프로퍼티)에 접근하고, 객체의 행동을 정의한다는 의미
    - 호출되는 객체에 따라 동작이 달라질 수 있음
    - 객체의 상태를 변경하거나 객체로부터 정보 가져오기 가능

⇒ 모든 메서드는 함수이지만, 모든 함수가 메서드는 아니다



# 2. 문제 상황 및 트러블슈팅

## 1) 문제 간단 설명

### ▶ 문제 상황

인텔리제이 업데이트한 이후 윈도우에서 인텔리제이가 검색되지 않음. *.java 파일을 우클릭해도 연결이 되지 않음

### ▶ 원인 및 해결

- 업데이트할 때 재설치 권장해서 *.exe 다운 받았고 설치 실행 파일이 2개 떴는데 그러면서 설치 위치가 꼬였나봐
- 검색이 안돼서 찾다가 윈도우 검색 인덱스가 꺼졌을 수 있단 말을 듣고 구글링 후 설정에서 다음을 발견함
- PC에서 파일을 검색할 때 포함하지 않는 폴더들 목록이 있는데 아니나 다를까 그 중 한 폴더에 새로운 인텔리제이가 설치되었더라. 삭제하고 재설치 완료.
    - 재설치할 때는 저기 들어가있지 않은, 일반적인 검색이 가능한 폴더로 알아서 잡아서 경로 추천하길래 그대로 설치 완료.
- 검색 안되는 게 생각 보다 불편하고 거슬려서 해결하느라 시간 꽤 많이 잡아 먹었네. 그치만 해결해서 속시원함.
