## 1. 오늘 내가 직접 손으로 치며 배운 점

- `UTF-8` : 기존에는 EUC-KR 등 독자적인 인코딩을 사용해
  다양한 언어를 사용할 수 없고 호환성이 떨어졌지만
  UTF-8을 통해 다양한 언어를 하나의 인코딩으로 편리하게 사용이 가능함

- `CPU 곱셈 나눗셈` : shift연산과 덧셈 뺄셈을 조합해서 처리한다

- `CPU 뺄셈` : 5 - 1을 한다면 1의 2의 보수를 더하고 자리올림을 버린다

- `해시 값` : 해시 함수를 통해 출력된 결과물
- `해시 함수` : 임의의 길이의 데이터를 입력받아 해시 값으로 변환하는 알고리즘
- `해시 특징`
	- 고정된 길이를 가진다
	- 동일한 데이터를 넣으면 똑같은 해시값이 나온다
	- 해시값만 가지고 원래 데이터를 복원할 수 없다
	- 한 글자만 바뀌어도 해시값은 완전히 다르게 나온다

- `Git 커밋 id를 정수형으로 안쓰고 hash를 쓰는 이유`
	- `Git은 오프라인에서도 사용이 가능해야 함`
	  정수형으로 쓰게 되면 이전 커밋의 id가 어떤 것인지 서버를 통해 확인이 필요함
	  하지만 해시 값을 쓰면 언제든 커밋이 가능함
	  하지만 순서를 기억할 수 없다 따라서 부모 해시 값도 같이 저장함
	- `데이터의 무결성 보장` : 단순히 임의로 부여되는 번호가 아니라
	  파일 내용, 작성자, 타임스탬프, 부모 커밋 등
	  다양한 데이터의 내용을 해시 함수를 통해서 생성해
	  단 한 글자라도 조작하면 코드 위변조를 감지 가능

- `데이터 무결성` : 오류, 변조, 손상 없이 정확하고 온전하게 믿을 수 있는 상태로 유지되는 것

| 단계      | 연산 내용        | 이진수 값       |
| :------ | :----------- | :---------- |
| **1단계** | 1의 2의 보수를 구함 | `1111`      |
| **2단계** | 5 + 1의 2의 보수 | `0001 0100` |
| **3단계** | 자리올림 버림      | `0100` = 4  |
